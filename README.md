焕琢、VARVAN 及后续网站共用的内容仓库。这里同时保存可公开的网站内容，以及仅供内部使用的品牌、商标和产品资料。

## 维护记录

推送者、日期和对应提交统一记录在 [PUSH_LOG.md](PUSH_LOG.md)。

## 目录结构

| 目录 | 用途 | 是否可公开 |
|---|---|---|
| `site/` | 网站前台可直接使用的内容、图片和页面结构 | 可以公开 |
| `internal/` | 商标、配方、供应商和品牌策略等内部资料 | 不对外公开 |
| `archive/` | 旧版本、测试文件、已淘汰方案 | 视具体文件而定 |

### `site/`

- `site/content/`：网站文案和数据，优先使用 Markdown、JSON 或 YAML。
- `site/assets/`：网站图片、视频、字体和图标等素材。
- `site/pages/`：首页、品牌页、产品页等页面结构与内容清单。

### `internal/`

- `internal/trademark/`：商标查询、注册号、审查报告和检索方法。
- `internal/product/`：产品需求、配方方向、打样和供应商资料。
- `internal/brand/`：品牌策略、命名、视觉提案和内部讨论。

### `archive/`

用于保存被替代的旧版本、测试文件和不再使用的方案。归档不删除历史，方便以后追溯。

## 现有文件暂不移动

当前根目录中的文件先保持原位，后续按主题逐批迁入对应目录：

- 商标档案、方法论文档和查重脚本：迁入 `internal/trademark/`。
- 抗衰产品需求、配方和检测资料：迁入 `internal/product/`。
- 品牌视觉提案和主视觉图片：迁入 `internal/brand/` 或 `site/assets/`，按是否可公开决定。
- `自然声音放松工具.html`：作为独立网页应用，后续迁入 `site/apps/`。
- `test-upload.md`、`codex-test.txt` 等测试文件：迁入 `archive/`。

迁移时一次只处理一类文件，并保留 Git 历史，避免覆盖其他人的提交。

## 内容边界

1. 只有确认可以对外发布的内容才能放进 `site/`。
2. 配方细节、供应商信息、成本、未公开商标信息和内部策略不要放进 `site/`。
3. 即使放在 `internal/`，也不要提交密码、API Key、访问令牌等敏感凭据。
4. 图片和音频入库时必须记录来源与授权状态。
5. 网站发布前先检查页面是否引用了内部文件。

## 协作规则

提交前先阅读 `GIT_RULES.md`。如果当前工作区尚未同步该文件，以线上 `origin/main` 的版本为准。推送前先 `git pull --rebase`，检查 `git status`，不要强制推送，不要删除不属于自己的文件。
